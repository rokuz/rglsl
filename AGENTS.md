# AGENTS.md — rglsl

> A Vulkan GLSL (450/460) → SPIR-V compiler in safe Rust, replacing glslang. Hard fork of naga 30.0.0.
> Out of scope: GLSL ES, other `#version`s, OpenGL semantics.

If `AGENTS.local.md` exists, read it too: it has the maintainers' local workflow.
Adding a GLSL extension: `EXTENSIONS.md`.

## Layout

| Path | What |
|---|---|
| `rglsl/` | the compiler: IR, GLSL frontend (`src/front/glsl`: lowering of `rglsl-sema`'s analysis to IR), validator, SPIR-V backend (`src/back/spv`, the only backend) |
| `rglsl-pp/` | GLSL preprocessor: macros, conditionals, `#include`, source map |
| `rglsl-ast/` | GLSL AST, parser and printer; shared by the compiler frontend and the fuzzer |
| `rglsl-sema/` | semantic analysis over the AST: scopes, types, built-ins, expression typing, diagnostics |
| `rglsl-link/` | the linker: merges object modules (`rglsl::object::ObjectModule`) into programs, object file format; the compiler API (`src/compiler`: `CompileOptions`, `ProgramOptions`, `Compiler::{compile_unit, preprocess, build}`, glslang-style diagnostics, depfiles) and glslang's reflection (`src/reflect`) |
| `rglsl-opt/` | the optimizer of linked IR (`-O`, `-Os`): one table of passes (`PASSES`), presets per level as tables of steps (`PRESETS`), target GPU profiles (`PROFILES`: `TargetGpu`), the pass manager (`optimize`: a preset or `--opt-passes` on every stage after linking, IR validation after each pass with `--opt-validate-each`, compaction and validation once at the end); called by `rglsl-link` before SPIR-V generation, never on objects |
| `rglsl-dis/` | text forms of SPIR-V: glslang's `-H` disassembly (`src/glslang`), SPIRV-Tools' `spirv-dis` form (`src/standard`, `--spirv-dis`) and hexadecimal text (`-x`, `--vn`) |
| `tests/link/` | link tests: modules, `expect`, optional single-file `reference.*` for exec |
| `tests/exec/` | exec tests with expected values (cooperative matrices and vectors, tensors, barycentrics, code generation options); an optional `options` file holds command-line options for glslang and rglsl |
| `rglsl-fuzz/` | port of GraphicsFuzz's variant generator and reducer (Apache-2.0) |
| `rglsl-fuzz/fuzz/` | the cargo-fuzz targets (crate `rglsl-libfuzzer`): `glsl_parser`, `ir`, `object`, `glsl_variant` |
| `rglsl-types/` | types shared by the rglsl crates (`ShaderStage`, ...) and the GLSL extension registry (`src/extension.rs`: one row per extension) and the reader and writer of the `.rglo` object file text (`src/rglo`) |
| `rglsl-derive/` | `#[derive(Rglo)]`: the `.rglo` encoding and decoding of a type, from its definition and `#[rglo(...)]` attributes |
| `rglsl-cli/` | the `rglsl` command-line tool, `glslangValidator`-compatible for Vulkan GLSL; it maps its options to the API of `rglsl-link` and `rglsl-dis` and only reads and writes files |
| `rglsl-capi/` | the C API of `rglsl-link` and `rglsl-dis`: library `rglsl_c` (cdylib, staticlib), header `include/rglsl.h` generated by cbindgen (`cargo xtask capi-header`) |
| `samples/` | runtime use of the compiler through `rglsl-link`'s `compile`/`link_spirv`; `samples/run.sh` runs them (CI); `samples/c/` uses the C API from C and C++ (`samples/c/run.sh`) |
| `rglsl-test/`, `rglsl/tests/` | upstream snapshot tests |
| `xtask/` | project automation: `cargo xtask oracles`, `cargo xtask test`, `cargo xtask snapshots`, `cargo xtask cli`, `cargo xtask builtins`, `cargo xtask fuzz`, `cargo xtask capi-header`, `cargo xtask gen-spirv`, `cargo xtask recursion`, `cargo xtask bench`, `cargo xtask opt-quality` |
| `xtask/harness/` | in-process harnesses of `cargo xtask bench --in-process`: rglsl (crate `rglsl-bench-harness`) and glslang (`glslang.cpp`, with `spirv-opt`'s performance passes as a separate phase) |
| `oracles.toml` | pinned glslang / SPIRV-Tools / SPIRV-Headers, KosmicKrisp, Amber and the ML emulation layer; built into `target/oracles/bin`: `glslang`, `spirv-val`, `spirv-as`, `spirv-dis`, `spirv-opt` and `glslang-opt` (the pinned glslang with the optimizer, for `bench` and `opt-quality` only; corpus comparisons use `glslang`) |

## Rules

- **No comments.** Do not write comments in code (`//`, `///`, `/* */`), in tests or in
  scripts, unless explicitly asked. Names and structure carry the meaning; rationale goes in
  commit messages. Existing comments are left alone unless asked to remove them.
- **Safe Rust only.** `unsafe_code` is forbidden in every crate (workspace lints, and
  the `rglsl` crate's own `[lints]`). Do not add `allow(unsafe_code)`. The one exception is the
  C boundary: `rglsl-capi` denies `unsafe_code` in its own `[lints]` and allows it only on
  `src/ffi.rs` (and its tests, which call the C functions). That module only turns raw pointers
  into references, slices and boxes, one operation per `unsafe` block, and calls the include
  callback; all logic, argument checks and `catch_unwind` are in the safe `src/api.rs`. After
  changing an exported function or type, run `cargo xtask capi-header` and commit the header.
- **No panics on user input.** A crash in the corpus run is always a bug.
- **Recursion over input structure only through `rglsl_types::stack::recurse`.** A stack
  overflow aborts the process. Every pass — preprocessor, AST, sema, lowering, fuzzer, IR
  (`Block` drop and clone), `proc`, compaction, validator, uniformity analysis, SPIR-V backend,
  linker, object files — walks nesting either with loops and work lists or with plain recursive
  functions in which every recursive call goes through `recurse(|| ...)`. The wrapper (built on
  `stacker`, as in rustc) runs the call on the current stack while at least `RED_ZONE` bytes are
  left and otherwise continues it on a new stack segment of `SEGMENT` bytes on the heap; callers
  do not know where they run. So the stack used between two `recurse` calls on any path,
  including the leaf work below the last one, must stay well under `RED_ZONE` in a debug build:
  a function with a large frame gets its own `recurse`. Recursion without the wrapper is fine
  only over structure bounded by a small constant (vector sizes, matrix columns). There are no
  artificial nesting limits; only glslang's preprocessor limits (macro expansion depth 200, `#if`
  nesting 65) are kept for parity.
  `rglsl-link/tests/nesting.rs` runs the whole pipeline at 10,000 levels on a 256 KiB debug
  stack in `cargo test`, and at 100,000 levels in release behind `--ignored` (CI runs it): add a
  case for every new kind of nesting, and replace a scan per level (quadratic at depth) with an
  index or a memo. `cargo xtask recursion` checks the call graph: every cycle goes through
  `recurse` or is listed with its reason and bound in `xtask/recursion-allowed.toml`.
- **No `unwrap` or `expect` anywhere, no other panics in non-test code.** `unwrap`, `expect`,
  `panic!`, `unreachable!`, `unimplemented!` and `todo!` are denied by clippy in every crate;
  return a `Result` instead, and never a silent default that hides a broken invariant.
  `unwrap`/`expect` (and `unwrap_err`/`expect_err`) are banned in tests too (`clippy.toml`):
  tests and their helpers return `Result` and use `?`, an `Option` becomes an error with
  `ok_or`/`context` or a `let ... else`, and `unwrap_or_else(|| panic!(..))` is no way around
  it. Tests may still fail with `assert!`/`panic!`. The only exception is the arena handle
  overflow in `Handle::from_usize`, an allocation limit like `Vec::push`.
- The compiler is called **rglsl** everywhere (crates, binary, docs); "naga" only names
  the upstream project it was forked from.
- Keep the IR's style: arenas, typed handles, exhaustive `match`, `Result` errors.
- **Exhaustive `match` only where every variant needs its own handling**: the dispatchers
  over `Expression` and `Statement`, operand visitors (`ir::visit`, `ir::block`, `compact`,
  `valid::handles`, which keep `clippy::wildcard_enum_match_arm`), SPIR-V writing of an IR
  node. A predicate or a check that cares about a few variants uses `matches!`, `if let` or a
  method on the enum (`TypeInner::is_handle`, `ScalarKind::is_integer`,
  `Statement::is_terminator`, ...) with `_` for the rest, never a list of every other variant;
  a question asked in more than one place becomes such a method.
- SPIR-V is the only output for now. Do not add other backends yet. IR features must be
  expressible in SPIR-V; keep SPIR-V encodings (opcodes, decorations, capabilities, raw words)
  in `back/spv`, not in the IR, when that costs nothing. What an instruction needs (SPIR-V
  extensions, capabilities, the SPIR-V version that makes an extension core or that is the
  minimum) is a row of `back/spv/feature.rs`, used as `writer.require(&feature::X)`; extension
  names are spelled only there. Enumerants the `spirv` crate lacks come from the generated
  `back/spv/grammar.rs` (add the name to `xtask/src/gen_spirv/backend.rs`, run
  `cargo xtask gen-spirv`), never as literal numbers.
- Every command-line option that changes what is compiled is an option of the Rust API
  (`rglsl_link::CompileOptions`, `ProgramOptions`) and of the C API; every output form (SPIR-V,
  disassembly, reflection, hexadecimal text, diagnostics, depfile, resource limits) is a library
  function in Rust and C. The command line only parses arguments and does process I/O.
- What glslang turns into SPIR-V that Vulkan does not allow is rejected with a short, clear
  error ("<thing> is not supported: <reason>"), never silently replaced by something else.

## Commands

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
RUSTFLAGS="--cfg fuzzing" cargo clippy -p rglsl-libfuzzer --all-targets -- -D warnings
cargo test --workspace --all-features
cargo test --release -p rglsl-link --test nesting -- --ignored   # 100,000-level nesting
cargo deny check

cargo xtask oracles [--glslang-dir ../glslang] [--no-exec]   # pinned glslang, glslang-opt, spirv-val, spirv-as,
                                                   # spirv-dis, spirv-opt (+ exec oracles)
cargo xtask snapshots                                        # spirv-val on the SPIR-V snapshots of rglsl/tests
cargo xtask test [--glslang-dir ../glslang] [--no-exec]      # glslang's corpus (+ exec on the local GPU)
cargo xtask test --filter NAME --no-progress-file            # quick check of some shaders
cargo xtask cli [--glslang-dir ../glslang]                   # glslangValidator command lines: rglsl vs glslang
cargo xtask builtins [--filter NAME] [--version N] [--stage EXT] [--all-overloads]
                                                   # every built-in function prototype and variable
                                                   # of rglsl-sema and of glslang's symbol table in a
                                                   # minimal shader: rglsl vs glslang (accepted,
                                                   # spirv-val, capabilities, extensions, operations);
                                                   # known divergences with their reason in
                                                   # xtask/builtins-expected.toml; target/xtask/
                                                   # builtins.tsv, builtins-coverage.tsv (one side only)
cargo xtask capi-header [--check]                            # regenerate (or check) rglsl-capi/include/rglsl.h
cargo xtask recursion [--no-build] [--verbose]               # call graph of the workspace from LLVM IR
                                                   # (target/xtask/recursion): fails on every
                                                   # cycle that does not go through stack::recurse
                                                   # and is not allowed in
                                                   # xtask/recursion-allowed.toml (reason, bound);
                                                   # a recursive type's drop glue must be cut by a
                                                   # Drop impl that drops the nested values inside
                                                   # recurse (rglsl-ast/src/deep.rs, ir::Block)
cargo xtask gen-spirv [--check]                              # regenerate (or check) the SPIR-V tables from the
                                                   # pinned SPIRV-Headers and glslang in target/oracles:
                                                   # rglsl/src/back/spv/grammar.rs (enumerants the
                                                   # `spirv` crate lacks; names listed in
                                                   # xtask/src/gen_spirv/backend.rs) and
                                                   # rglsl-dis/src/glslang/glslang_tables.rs (-H) and
                                                   # rglsl-dis/src/standard/grammar.rs (--spirv-dis,
                                                   # from SPIRV-Headers' grammars and spir-v.xml)
SPIRV_VAL=target/oracles/bin/spirv-val sh samples/c/run.sh   # C and C++ samples (SANITIZE=address, LEAKS=1 on macOS)
cargo xtask bench [--runs N] [--filter NAME] [--debug-info g|gVS]
                                                   # compile time against glslang and glslang -O, one
                                                   # process at a time, optimizer budget (glslang -O −
                                                   # rglsl): target/xtask/bench.md and bench.tsv
cargo xtask bench --in-process [--runs N] [--filter NAME] [--debug-info g|gVS]
                                                   # the same in one process each (no start-up),
                                                   # first and steady compiles, rglsl phases, glslang's
                                                   # spirv-opt phase: target/xtask/bench-in-process.md, .tsv
cargo xtask opt-quality [--filter NAME]                      # SPIR-V counts of rglsl, spirv-opt -O/-Os of rglsl's
                                                   # module and glslang -O on every shader rglsl compiles,
                                                   # spirv-val on each: target/xtask/opt-quality.md, .tsv
cargo xtask opt-quality --exec [--exec-target T] [--runs N]  # and on the Vulkan targets: driver statistics (Amber
                                                   # --pipeline-stats), GPU and pipeline creation time,
                                                   # exec equivalence of spirv-opt -O(rglsl) and glslang -O
                                                   # with rglsl: target/xtask/opt-quality-exec.md, .tsv

cargo xtask fuzz --shaders DIR [--exec]                      # differential fuzzing against glslang (+ exec)
cargo xtask fuzz --libfuzzer TARGET [--time SECS] [--jobs N] # cargo +nightly fuzz run
cargo xtask fuzz --decode INPUT                              # glsl_variant input -> shader family
cargo xtask fuzz --reduce JOB.json --interesting K           # GraphicsFuzz reducer
```

Per-shader results of the last corpus run: `target/xtask/results.tsv`. Fuzzer findings of every
mode: `target/xtask/fuzz/`.
